# DX, onboarding y documentación — Auditoría Cortex

## Valoración

La documentación de Cortex está **muy por encima de la media de un producto interno**.
El `README.md` (710 líneas) combina una parte operativa (instalar/usar/operar) con una
guía formativa excepcional que enseña RAG, embeddings, grafos y agentes desde cero, con
recuadros «⚠️ Qué mirar» que documentan con honestidad los límites reales (local
no-semántico, sin índice ANN, scores RRF no comparables, umbrales a calibrar).
`CONTRIBUTING.md` ofrece un mapa claro «quieres X → toca Y», recetas frecuentes y la regla
de oro de dependencias (`core` no importa `agents`). La consistencia doc↔código casa bien
en los puntos clave verificados (8 tools MCP en README y `server.ts`; toolbelt; flags de
`cortex link`; formato `.cortex.json`). Un dev nuevo puede instalar, entender y contribuir
con poca fricción. **No está a la altura de primera línea en el pulido**: el flujo estrella
`curl|sh` sorprende sin pre-aviso de prerrequisitos y persisten varias derivas doc↔código
menores que la propia `CLAUDE.md` («mantén la doc viva») debería haber cazado. Correcciones
de pulido, no estructurales.

## Hallazgos por severidad

### 🟡 Medio

**M1. El flujo estrella `curl|sh` clona por SSH un repo privado y hace checkout completo del monorepo, sin pre-aviso de prerrequisitos** — esfuerzo **S**
- **Evidencia:** `scripts/install.sh:8` usa `REPO_URL` por defecto `git@github.com:Dinacode-Labs/cortex.git` (SSH); `install.sh:23` hace `git clone` completo y `install.sh:27` `pnpm install --silent`. El script aborta si falta `git`/`node` (`install.sh:14-15`) pero el README «Para developers» (`README.md:51-67`) presenta `curl -fsSL .../install.sh | sh` como instalación ligera de un «CLI + toolbelt» sin mencionar que requiere clave SSH dada de alta en la org, ni Node≥20/git.
- **Impacto:** Un dev sin clave SSH para la org (o sin Node≥20) ve fallar el comando estrella de onboarding con un error de git/clone poco evangélico. Además sorprende: el headline sugiere un cliente liviano cuando en realidad deja un checkout completo del monorepo en `~/.dinacode-cortex` y ejecuta el dev environment entero (los hooks corren `pnpm -C <repo> --filter …`).
- **Recomendación:** Documentar en README los prerrequisitos del flujo `curl|sh` (Node≥20, git, acceso SSH a la org) y que deja un checkout completo bajo `~/.dinacode-cortex`. Soportar clonado HTTPS como fallback o detectar la ausencia de clave y emitir un mensaje claro («configura tu clave SSH de GitHub»). Mover el aviso de prerrequisitos al propio script, antes del clone.

**M2. `CLAUDE.md` desfasada: dice «5 tools corporativas» cuando son 8** — esfuerzo **S**
- **Evidencia:** `CLAUDE.md:34` — «`mcp-server/ # servidor MCP (stdio) con las 5 tools corporativas`». `server.ts` registra 8 (`registerTool` en líneas 53, 76, 96, 122, 143, 164, 193, 218) y el `README.md:128` ya dice correctamente «Tools MCP (8)».
- **Impacto:** `CLAUDE.md` es el documento que leen los agentes de IA antes de operar el repo; la propia guía exige «mantenla actualizada… verifica que el fichero/función/flag citado sigue existiendo». Un dato numérico erróneo en la guía-para-agentes propaga información obsoleta justo a quien más la usa.
- **Recomendación:** Actualizar a «8 tools», o mejor eliminar el número y enlazar la tabla del README como fuente única para que no vuelva a divergir. Aprovechar para la poda rápida de `CLAUDE.md` que ella misma pide.

### 🟢 Bajo

**B1. El README omite el conector `connect-meeting`, que sí existe en el CLI** — esfuerzo **S**
- **Evidencia:** `apps/cli/src/index.ts:29` registra `connect-meeting` (script `packages/agents/src/connect-meeting.ts`, help «transcribir + destilar grabaciones de reunión a conocimiento tipado»), pero la sección «Ingesta de fuentes» (`README.md:182-187`) solo lista connect-github/connect-docs/connect-notion/connect-sessions.
- **Impacto:** Una capacidad real queda invisible desde el README; un dev que no ejecute `cortex --help` no sabe que existe. Incoherencia doc↔CLI que mina la confianza en que el README sea exhaustivo.
- **Recomendación:** Añadir la fila `cortex connect-meeting "<slug>" <ruta-audio/vídeo>` a la tabla de conectores del README, o marcar explícitamente que se omite por ser experimental.

**B2. Inconsistencia de naming en la ayuda del CLI: muestra `cortex:link` (pnpm) en vez de `cortex link`** — esfuerzo **M**
- **Evidencia:** El dispatcher se invoca como `cortex <sub>` (`apps/cli/src/index.ts`), pero los scripts destino imprimen uso/errores con la forma pnpm: `link.ts:36,61,99,118` («Uso: cortex:link --create …»). El patrón general mezcla ambas formas en README/CLAUDE/scripts (`cortex sync` en `README.md:150` vs `pnpm cortex:sync` en `scripts/cortex-sync.ts:11`).
- **Impacto:** Un dev que instaló vía `curl|sh` solo conoce el comando `cortex` (el shim del PATH); cuando un script le responde «Uso: cortex:link --create», ese comando con dos puntos NO existe en su PATH y le confunde. Dos sintaxis para lo mismo erosiona la ergonomía.
- **Recomendación:** Unificar los mensajes de uso de los scripts a la forma `cortex <sub>` cuando se invocan vía el dispatcher (pasar el nombre invocado o detectar el shim). Como mínimo, usar consistentemente `cortex link`/`cortex sync` en toda la doc orientada a devs y reservar `pnpm cortex:*` para la sección de infra.

**B3. CONTRIBUTING afirma «Incremental por sourceReference» para los conectores, lo cual es engañoso** — esfuerzo **S**
- **Evidencia:** `CONTRIBUTING.md:40` — «Reutiliza la capa extract … Incremental por sourceReference». En realidad el dedup incremental es server-side (`capture.ts` salta por `source_reference`), pero la extracción de IA cara (visión/whisper/OCR/parse) se RE-EJECUTA en cada run porque no hay manifiesto/caché local.
- **Impacto:** Un contribuidor que añada un conector siguiendo esta receta asumirá que re-ejecutar es barato y no implementará caché de extracción, perpetuando el re-pago de IA. La doc induce a una decisión de diseño incorrecta.
- **Recomendación:** Matizar: «el guardado es idempotente por sourceReference (el servidor deduplica), pero la EXTRACCIÓN no es incremental: añade un manifiesto/caché local si la fuente es cara (visión/audio)». Alinear con la nota equivalente del README.

**B4. Comentarios de código desfasados respecto al comportamiento real** — esfuerzo **S**
- **Evidencia:** `apps/cli/src/auth.ts:9` — «Lo usarán hooks/CLI/MCP para firmar las escrituras … cuando migren a la API HTTP», pero la migración ya ocurrió (`README.md:108-109` y `176-180`: los hooks/conectores YA escriben por la API autenticada). `email.ts` documenta volcar el OTP por stderr pero usa stdout.
- **Impacto:** Comentarios que describen un estado futuro/pasado inexistente confunden al siguiente dev sobre qué es vigente. Baja gravedad individual, pero es justo la deriva que la política «el código manda sobre la doc» quiere evitar.
- **Recomendación:** Poda de comentarios «cuando migren…»/TODO ya resueltos en `apps/cli` y `packages/core`; al menos corregir `auth.ts:9` y la discrepancia stdout/stderr de `email.ts`.

**B5. `git pull --ff-only || true` en el instalador silencia fallos de actualización** — esfuerzo **S**
- **Evidencia:** `scripts/install.sh:21` — `git -C "$DEST" pull --ff-only --quiet || true`. Si el checkout local tiene cambios o divergió, el pull falla y se ignora; el dev sigue ejecutando una versión vieja del repo sin enterarse.
- **Impacto:** Re-ejecutar el instalador (el patrón recomendado para actualizarse) puede dejar al dev silenciosamente en código obsoleto, con un CLI/hook que no coincide con el servidor. Diagnóstico difícil («ya actualicé y sigue fallando»).
- **Recomendación:** Avisar cuando el pull falla («no pude actualizar $DEST: tienes cambios locales / divergencia») en vez de tragárselo con `|| true`. Para un cliente, considerar clone limpio o `git fetch && git reset --hard origin/main` con confirmación.

**B6. Sin LICENSE ni plantillas de PR/issue para encauzar el flujo de contribución descrito** — esfuerzo **S**
- **Evidencia:** No existe `LICENSE*` en la raíz ni `.github/ISSUE_TEMPLATE/` (solo `.github/workflows/ci.yml`). `CONTRIBUTING.md:68-74` describe un flujo de PR con checklist («qué cambia, por qué, cómo lo verificaste») pero nada lo materializa como plantilla.
- **Impacto:** Para un producto interno la licencia es menos crítica, pero la ausencia de `PULL_REQUEST_TEMPLATE` deja el buen checklist de CONTRIBUTING como mera recomendación: los PRs olvidan la sección de verificación y la actualización de docs que el repo exige.
- **Recomendación:** Añadir `.github/PULL_REQUEST_TEMPLATE.md` con el checklist de CONTRIBUTING (typecheck/tests en verde, docs actualizadas, cómo verificado). Añadir un LICENSE o NOTICE interno aunque sea propietario, para dejar claro el régimen.

## Qué está bien

**README + guía formativa de calidad excepcional con honestidad sobre límites** (🟢 Bien)
- **Evidencia:** `README.md:256-710` — guía formativa con 10 secciones y recuadros «⚠️ Qué mirar» (local no-semántico `README.md:369-385`, scores RRF no comparables `README.md:426-432`, umbrales a calibrar `README.md:632-635`) + checklist de evaluación `README.md:687-710`.
- **Impacto:** Un dev nuevo puede entender la tripa de Cortex (RAG, embeddings, grafo, bi-temporal, agentes) sin experiencia previa y, sobre todo, JUZGAR dónde están los límites reales en vez de tragarse marketing. Es un activo de onboarding poco común que reduce drásticamente el ramp-up y la deuda de conocimiento tribal.
- **Recomendación:** Mantenerlo como estándar a preservar: cada nueva capacidad debería traer su sección práctica y, si toca conceptos, su recuadro «Qué mirar». No dejarlo crecer sin podar (vigilar que las cifras citadas, p.ej. las 266/147 del proyecto piloto, no caduquen).

Otros aciertos verificados: las 8 tools MCP del README coinciden con `server.ts`; la tabla
del toolbelt coincide con `config/toolbelt.json` (5 MCPs + 6 skills); los flags de
`cortex link` (`--create/--private/--parent/--ignore/<slug>`) coinciden con `link.ts`;
`.cortex.json` usa el formato slug-aware que el README promete; el dispatcher `cortex`
estilo `gh` y el flujo `cortex link`/`cortex ui` (ticket de un solo uso) están bien diseñados.
